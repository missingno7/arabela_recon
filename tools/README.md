# Acquired tools

The pinned executable installations are under `C:\tools`. Acquisition archives
and extracted dependencies remain local and are ignored by Git. Only this
setup document is versioned in `tools/`. [scripts/check_tools.py](../scripts/check_tools.py)
contains the required executable paths, source URLs and SHA-256 hashes;
`oracle/toolchain.json` is generated from those declarations during a build.

The scripts currently use the Python installation at
`C:\Users\Jiri\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`.
For another machine, adjust `$taskPython` in `scripts/build.ps1`.
Install Capstone 5.0.9 into `tools/pylib` for disassembly
(`python -m pip install --target tools/pylib capstone==5.0.9`); Pillow is needed
only for the optional logo rendering. NASM is expected at
`tools/nasm/nasm-2.16.03/nasm.exe`; the other DOS tools use the paths pinned in
`scripts/check_tools.py`.

- `tp6-disk1.json` / `.img`: PCjs installation disk; `scripts/pcjs_disk.py`
  reconstructs FAT12 and extracts its installation files.
- `lzexe90.zip` / `lz90`: the original 0.90 archive and documentation.
- `unlzexe8.zip` / `unlzexe8`: independent DOS unpacker, version 0.8.
- `unlzexe.c`: upstream UNLZEXE source consulted for the host unpacker.
- `dosbox-installer.exe`: official DOSBox 0.74-3 Windows installer, extracted
  with 7-Zip to obtain a portable execution environment.
- `nasm.zip` / `nasm`: pinned NASM 2.16.03 from the official release archive.
  Used only for a data-only OMF object containing graphics coordinates.
  All executable instructions are generated by TP6. Its documented Borland
  Pascal segment restrictions explain the `CODE` segment name in the object:
  https://www.nasm.us/doc/nasm10.html#section-10.5.2

Abandoned archive searches and duplicate extracted installations were removed.
UNLZEXE 0.5 hung in MS-DOS Player; the corrected 0.8 succeeds. A 0.91 support
archive was initially consulted for its unpacker only; it was never used as
the packing oracle. The raw canonical 0.90 packing mismatch remains in
`build/roundtrip/comparison.json`; it is not discarded or normalized silently.
